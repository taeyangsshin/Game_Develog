# 게임 프레임워크 v0.1 — 반려동물 미용 스토리 게임

작성일: 2026-10-26
상태: 설계 초안 / 실행 가능한 게임 프로젝트는 아직 없음
플랫폼: PC 우선
화면: 2D 대기실 + 간단한 3D 미용 + 2D 대화·결과·기록
개발 엔진: 미정. Unity는 후보이며 설치·버전·팀 경험 확인 후 확정한다.

## 1. 이번 기획의 기준

### 사용자가 정한 방향

- PC에서 먼저 만든다.
- 짧은 에피소드로 플레이하며 전체 이야기에는 엔딩이 있다.
- 털의 질감과 실제로 미용하는 듯한 조작 감각이 핵심이다.
- 2D 대기실에서 동물을 만나고 미용할 때는 3D로 전환한다.
- 동물별 친밀도와 미용 기록을 저장한다.
- 강아지와 고양이를 모두 고려하며 강아지 / 고양이 / 혼합의 방문 구성을 검토한다.

### 아직 확정하지 않은 것

- 엔진과 버전, 최소 PC 사양, 인원·일정.
- 게임 이름과 주인공, 단골 캐릭터의 이름·성격.
- 제안한 '미용실에서의 일주일과 마지막 기념사진' 스토리의 채택 여부.
- 에피소드 수와 1회 플레이 시간.
- 첫 품종과 첫 도구, 털 표현 기술.
- 세 방문 구성을 처음부터 열지, 스토리 후 자유 미용에서 열지.
- 염색·액세서리의 범위와 판매 여부. 현재 PC 완결형 구조에 맞춰 나중에 재검토한다.

## 2. 게임 전체 흐름

타이틀 → 새 게임 / 이어하기 → 방문 구성 선택 → 2D 대기실 → 2D 대화·요청 → 3D 미용 → 결과·사진 → 친밀도·기록 저장 → 다음 에피소드 → 엔딩

- 선택한 동물의 ID와 해당 방문의 ID를 화면 전환 동안 유지한다.
- 이전 방문과 친밀도는 다음 방문의 대사·반응에 연결한다.
- 실제 시간의 출석이나 접속 시간으로 스토리를 강제로 진행시키지 않는 구조를 우선 검토한다.
- 첫 구현에서는 임시 도형과 버튼으로 화면 이동만 검증한다. 이 단계 완료는 털 미용 구현 완료를 뜻하지 않는다.

## 3. 화면은 여섯 가지로 나눈다

| 화면 | 역할 | 첫 버전 |
| --- | --- | --- |
| 타이틀·방문 구성 | 새 게임·이어하기, 강아지·고양이·혼합 선택 | 처음에는 강아지 테스트만 활성화해도 된다. |
| 2D 대기실 | 동물 카드·이름·친밀도·방문 이력, 손님 선택 | 카드 한 장 |
| 2D 대화·요청 | 짧은 사연과 오늘 손질할 내용 | 대사와 요청 한 개 |
| 3D 미용 | 도구 선택·접촉·털 손질·관찰 | 임시 모델과 도구 한 개 |
| 2D 결과·앨범 | 손질 전후 모습·기록·관계 변화 | 결과 한 장 또는 간단한 상태 표시 |
| 엔딩 | 이전 기록을 활용해 관계의 결실 보여주기 | 시나리오 확정 후 구현 |

별도 화면을 반드시 별도 씬으로 만들 필요는 없다. 엔진을 정한 뒤 화면 패널과 씬의 배치를 결정한다.

## 4. 세 모드는 방문 구성 설정으로 처리한다

설정 값: DogOnly / CatOnly / Mixed

- 공통 화면, 미용 도구의 기본 입력, 저장과 결과 시스템을 재사용한다.
- 동물 데이터의 species를 확인해 해당 방문 구성에 맞는 손님을 고른다.
- 고양이 손질은 강아지 작업을 그대로 복사하지 않고 별도 조사에 따라 제공 작업을 정한다.
- 스토리의 필수 인물이 선택 때문에 누락되지 않도록 에피소드에 대체 가능한 손님 자리를 설계하거나 해당 모드를 자유 미용으로 한정한다. 최종 방식은 시나리오와 함께 결정한다.
- 개·고양이·혼합마다 저장 데이터를 세 벌 복제하지 않는다. 새 게임별 저장 슬롯에 선택한 설정과 개별 동물 기록을 보관한다.
- 첫 시험 버전에 고양이가 없으면 선택지를 잠시 비활성화하고 '준비 중'을 표시한다. 지원하지 않는 모드로 빈 화면에 들어가게 하지 않는다.

## 5. 기능은 작은 역할로 나눈다

| 기능 | 책임 |
| --- | --- |
| GameFlow | 현재 화면·에피소드·선택한 방문을 관리한다. |
| PetCatalog | 동물의 종·품종과 기본 외형 정보를 제공한다. |
| PetState | 개별 동물의 친밀도·방문 기록·적용 외형을 유지한다. |
| VisitSession | 오늘 요청과 손질 전·진행 중·완료 상태를 관리한다. |
| GroomingController | 도구 입력과 접촉을 받아 털 변화 기능에 전달한다. |
| CoatState | 특정 동물의 털 변화 데이터를 유지한다. |
| StoryProgress | 본 대화·끝낸 에피소드·엔딩 조건을 기록한다. |
| SaveService | 저장·불러오기와 데이터 버전을 관리한다. |

엔진 확정 후 코드로 옮길 논리적인 역할 목록이다. 지금부터 매 역할마다 별도 복잡한 관리자를 만드는 것은 아니다.

## 6. 데이터에서 가장 중요한 구분

### 바뀌지 않는 기본 정보

- petId: 개별 동물을 구분하는 고유 ID.
- species: Dog 또는 Cat.
- breedId: 품종과 연결할 ID.
- displayName: 이름.
- portraitAssetId / modelAssetId: 같은 동물의 2D 이미지와 3D 모델.
- coatProfileId: 털 유형.
- individualTraits: 이 동물의 성격과 반응. 품종 전체의 성격으로 단정하지 않는다.

### 플레이하며 바뀌는 정보

- affection: 친밀도.
- completedVisitIds: 완료한 방문 ID 목록.
- appearanceState: 현재 털 스타일·색·액세서리.
- groomingState: 저장 지원 범위에 맞춘 털 변화 데이터.
- history: 요청·결과·사진 ID·에피소드 기록.

### 저장 파일의 구성 예시

- schemaVersion: 저장 형식 버전.
- selectedAnimalMode: 방문 구성.
- storyProgress: 진행한 에피소드와 선택.
- pets: petId를 기준으로 한 개별 상태.
- completedVisits: 중복 완료와 중복 보상 방지용 기록.
- activeVisit: 중간 작업 재개를 지원할 때의 세션.
- album: 사진 경로 또는 사진 ID.

완료한 방문이 다시 처리돼 친밀도가 중복 증가하지 않게 한다.
결과 사진만 저장하는 것과 실제 3D 털 상태를 복원하는 것은 별도로 구현·검증한다.

## 7. 털 손질 체험의 최소 규칙

1. 도구를 선택한다.
2. 마우스가 모델의 어느 부분을 가리키는지 찾는다.
3. 도구가 닿아 작동하는 동안에만 해당 영역을 변경한다.
4. 지나간 경로·범위·방향에 맞게 외형과 소리를 반응시킨다.
5. 이미 손질한 상태가 계속 유지된다.
6. 결과와 기록을 같은 동물 ID에 연결한다.

첫 실험은 작은 털 영역에서 한다. 다음 둘을 구분해 확인한다.
- **조작 검증:** 임시 도형을 눌러 변화시킬 수 있다.
- **핵심 체험 검증:** 털이 보이고 직접 손질해 모양을 바꾼다는 느낌이 난다.

첫 도구는 클리퍼 또는 빗 중 하나를 정한다. 실제 품종·동물에 맞는 손질 작업인지 조사한 뒤 적용한다.

## 8. 스토리의 틀 — 제안

장소 하나의 미용실에서 단골들이 반복 방문한다.
방문마다 대화 한 토막과 짧은 손질이 있고, 친밀도와 기록이 다음 방문에 반영된다.
마지막 에피소드에서는 처음과 마지막 사진·반응을 비교해 관계의 변화를 보여준다.

'일주일 동안 가게를 맡고 마지막 기념사진을 남긴다'는 앞선 제안은 후보 시나리오다. 게임 이름, 일수와 캐릭터는 확정하지 않았다.

## 9. 단계별로 천천히 만들기

### M0 — 화면을 오가는 빈 뼈대

- 타이틀의 시작 버튼.
- 강아지 임시 카드 한 장을 가진 2D 대기실.
- 선택한 petId가 표시되는 3D 미용 공간.
- 대기실로 돌아가는 버튼.

**완료 기준:** 같은 동물을 선택해 들어갔다가 돌아올 수 있고 선택 상태가 맞다.

### M1 — 작은 털 손질 체험

- 작은 털 영역과 도구 하나.
- 접촉한 경로에만 변화.
- 도구가 떨어지면 변화 중단.

**완료 기준:** 완료 게이지 없이도 손질 전후 차이를 알아보고 스스로 더 다듬을 곳을 찾는다.

### M2 — 한 마리와 친밀도·저장

- 방문 완료 시 친밀도와 기록 갱신.
- 종료 후 불러오기.
- 같은 방문 중복 완료 방지.

**완료 기준:** 재실행 후 같은 동물과 완료 기록을 복원한다.

### M3 — 짧은 에피소드 하나

- 대화·요청 → 미용 → 결과 → 다음 방문 연결.

**완료 기준:** 설명 없이도 한 편을 끝낼 수 있다.

### M4 — 고양이와 방문 구성

- 고양이 기본 정보·이미지·모델과 적합한 손질 작업.
- 강아지 / 고양이 / 혼합 필터.

**완료 기준:** 선택한 구성에 맞는 손님이 등장하고 두 동물의 저장 상태가 섞이지 않는다.

### M5 — 완결된 이야기

- 같은 단골의 재방문과 반응 변화.
- 최종 에피소드·앨범·엔딩.

**완료 기준:** 새 게임부터 엔딩과 이어하기까지 정상 진행된다.

첫 미술·꾸미기 실험은 병행할 수 있지만, 실제 결제와 다수의 품종·도구는 핵심 체험 검증 후 추가 범위를 정한다.

## 10. 다음에 할 일은 M0 하나

- [ ] 엔진·버전을 확정한다.
- [ ] 빈 프로젝트를 만든다.
- [ ] 시작 버튼이 있는 타이틀을 만든다.
- [ ] 임시 동물 카드 한 장을 만든다.
- [ ] 카드 선택 시 임시 모델이 있는 미용 공간으로 전환한다.
- [ ] 돌아가기 버튼으로 같은 동물의 대기실에 복귀한다.

M0가 끝나면 스크린샷과 실제 동작을 확인하고 일지에 기록한다. 다음은 M1이며, M0를 만든 것만으로 미용 기능이 구현됐다고 표시하지 않는다.

## 11. 엔진 확정 후 사용할 폴더 구성 예시

- Art/Portraits: 2D 동물 이미지.
- Art/Models: 3D 동물·도구 모델.
- Scenes: 화면과 미용 공간.
- Scripts/Flow: 화면·방문 진행.
- Scripts/Pets: 기본 정보와 개별 상태.
- Scripts/Grooming: 도구 접촉과 털 변화.
- Scripts/Story: 대화·에피소드.
- Scripts/Persistence: 저장·불러오기.
- Data/Pets / Data/Visits: 기본 설정 데이터.
- UI: 대기실·도구·결과 화면.

이는 예정 폴더 구조이며 실행 프로젝트가 생성된 상태는 아니다.

## 이번 기록의 완료 범위

PC 우선·고양이 포함 방향과 공통 구조·데이터·첫 작업을 정리했다.
시나리오와 세 모드의 구체적인 개방 시점은 제안이며, 엔진 프로젝트·코드·게임 에셋·실행 테스트는 아직 만들지 않았다.
