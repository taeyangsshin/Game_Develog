# 개발 계획 — 단계별 진행

수정일: 2026-10-29  
상태: 구현 전 계획 / 첨부 ZIP의 세부 작업을 현재 방향에 맞게 통합

현재 목표는 PC에서 짧은 에피소드로 플레이하고 엔딩에 도달하는 반려동물 미용 게임이다.
화면은 2D 대기실 + 간단한 3D 미용이며, 털을 직접 손질하는 느낌과 개별 동물의 친밀도·기록 저장을 핵심으로 둔다.
강아지·고양이·혼합 방문 구성을 검토한다. 엔진·버전·인원·일정은 아직 미정이며 Unity는 후보이다.
전체 구조와 데이터는 [프레임워크 v0.1](framework.md)을 따른다. ‘일주일과 기념사진’은 후보 시나리오다.

## ZIP 검토와 적용 기준

2026-10-29 제공된 Game_Develog-pet-grooming.zip의 문서 7개를 현재 저장소와 비교했다.
ZIP의 2026-10-26 초기안은 화면·플랫폼 미정, 목욕 우선, 저장 후반 순서였으며 현재 방향보다 이전 내용이다.
세부 조작·주문 판정·중복 보상 방지·재시작·플레이 테스트의 작업 기준은 현재 단계에 맞춰 보완했다.
ZIP의 목욕·건조 등 전체 미용 절차는 선택 확장으로 남긴다. ZIP 제공만으로 해당 기능이 출시 필수 범위로 확정된 것은 아니다.
검토 결과는 [2026-10-29 일지](devlogs/2026-10-29.md)에 기록한다.

## M0 — 화면을 오가는 뼈대

### 할 일

- [ ] 엔진·버전과 첫 테스트 실행 환경을 정한다.
- [ ] 플레이어의 역할, 첫 동물 한 마리와 방문 요청 한 개를 임시로 정한다.
- [ ] 2D 대기실 → 대화·요청 → 3D 미용 → 결과의 흐름을 종이에 그린다.
- [ ] 임시 도형으로 미용대·동물·카드·버튼을 배치한다.
- [ ] 타이틀에서 대기실로 이동한다.
- [ ] 카드 선택 시 같은 petId를 가진 3D 미용 공간으로 들어간다.
- [ ] 돌아가기 버튼으로 같은 동물의 대기실에 복귀한다.

### 완료 기준

한 마리를 선택해 들어갔다 돌아올 수 있고 선택한 ID가 유지된다. 처음부터 다시 실행해도 화면 이동이 정상이다.
임시 모델의 표시만으로 털 미용 기능을 완료했다고 기록하지 않는다.

## M1 — 작은 털 영역과 도구 하나

### 할 일

- [ ] 품종과 제공할 손질 작업에 맞는 도구 하나를 정한다.
- [ ] 도구 선택과 선택 상태 표시를 만든다.
- [ ] 클릭·드래그가 모델의 어느 부위에 닿는지 판별한다.
- [ ] 도구가 작동하며 닿아 있는 동안에만 해당 경로·범위의 털을 바꾼다.
- [ ] 잘못된 부위나 모델 밖에서는 털 상태를 바꾸지 않는다.
- [ ] 지나간 자리에 변화가 남고 소리·외형으로 반응을 보여준다.
- [ ] 다시 시작할 때 테스트 털 상태가 초기화되게 한다.

### 완료 기준

플레이어가 털을 보며 손질 전후 차이와 더 다듬을 곳을 알아본다. 도구를 떼면 변화가 멈추고 반복 입력으로 상태가 허용 범위를 벗어나지 않는다.
색 변화는 접촉 조작의 임시 검증에 쓸 수 있다. 부위 전체 모델을 한 번에 전환하는 것만으로 핵심 손맛 검증을 대체하지 않는다.
실제 털 한 올의 물리 계산이 필수는 아니며, 경로에 맞는 변화가 체감되는 표현 방식을 검증한다.

## M2 — 개별 관계와 저장

### 할 일

- [ ] 방문 전·진행 중·완료 상태를 분리한다.
- [ ] 같은 petId에 친밀도·손질 결과·방문 이력을 연결한다.
- [ ] 완료한 방문 ID를 기록해 같은 방문을 중복 처리하지 않는다.
- [ ] 결과 저장과 실행 종료 후 불러오기를 만든다.
- [ ] 결과 사진과 실제 털 상태의 저장 범위를 구분한다.
- [ ] 중간 작업 재개를 제공할지 정하고, 지원할 상태를 명시한다.

### 완료 기준

재실행 후 같은 동물의 친밀도와 완료 방문을 복원한다.
결과 버튼을 반복 눌러도 친밀도나 보상이 중복 지급되지 않는다. 보상 시스템을 채택하지 않으면 방문 완료의 중복 적용 방지만 확인한다.
저장하지 않는 작업 상태는 저장되는 것처럼 안내하지 않는다.

## M3 — 손님 한 명의 짧은 에피소드

### 할 일

- [ ] 짧은 대화와 요청 한 개를 작성한다.
- [ ] 작업 중 요청을 다시 확인할 수 있게 한다.
- [ ] 손질 가능한 범위와 결과에 반영할 기준을 정한다.
- [ ] 요청을 충족한 경우와 빠뜨린 경우를 결과에 구분해 보여준다.
- [ ] 대화·요청 → 손질 → 결과·저장 → 다음 방문을 연결한다.
- [ ] 새 방문 시작 때 방문 전용 상태를 초기화하고 개별 관계 기록은 이어간다.

### 완료 기준

처음 보는 사람이 기본 안내만으로 한 편을 끝낸다.
결과가 요청과 실제 손질 상태에 맞고 결과의 이유를 이해한다. 손님을 모두 씻기는 전체 미용 절차는 이 단계의 필수 조건이 아니다.
평가 점수·계산식·보상 종류는 별도 설계하며 아직 정해지지 않은 수치를 확정값처럼 넣지 않는다.

## M4 — 고양이와 방문 구성

### 할 일

- [ ] 고양이에 적합한 손질 작업과 털 특성을 별도로 조사한다.
- [ ] 강아지와 고양이의 2D 이미지·3D 모델·도구 반응을 준비한다.
- [ ] DogOnly / CatOnly / Mixed에 맞는 방문 대상을 선택한다.
- [ ] 필수 스토리 손님이 선택 때문에 빠지는 문제를 해결한다.
- [ ] 지원하지 않는 방문 구성은 비활성화하고 이유를 표시한다.

### 완료 기준

선택에 맞는 손님이 등장하고 동물별 상태와 기록이 섞이지 않는다.
세 구성을 처음부터 제공할지, 엔딩 뒤 자유 미용에서 제공할지는 시나리오와 함께 정한다.

## M5 — 완결된 이야기와 검증

### 할 일

- [ ] 단골의 재방문에 이전 친밀도·기록에 따른 반응을 연결한다.
- [ ] 앨범·손질 전후 비교·최종 에피소드·엔딩을 만든다.
- [ ] 필요한 표정·애니메이션·도구 소리·안내를 다듬는다.
- [ ] 새 게임·이어하기·재시작·방문 완료·엔딩까지 직접 확인한다.
- [ ] 다른 사람의 플레이에서 막히는 지점과 조작 실수를 기록한다.
- [ ] 수정 후 목표 PC에서 실행 파일을 확인한다.

### 완료 기준

새 게임부터 엔딩까지 진행되고, 종료 후 이어하기와 다시 시작이 정상이다.
단골과 쌓아 온 관계·기록이 마지막 장면에 드러난다. 완료 기록에는 빌드·시연·테스트 근거를 남긴다.

## 선택 확장 — 목욕·건조·추가 도구

아래는 ZIP에서 가져온 기능 후보다. 핵심 손맛과 저장을 먼저 검증한 뒤 채택 여부를 정한다.
실제 미용 절차는 별도 조사하고 게임용 단순화와 구분한다.

| 후보 | 작업 내용 | 채택할 경우 확인할 기준 |
|---|---|---|
| 목욕 | 얼룩 배치, 문지르기·거품·헹구기, 부위별 상태 | 반복 입력에도 완료 상태가 범위를 벗어나지 않고, 헹군 뒤 외형과 상태가 일치한다 |
| 건조 | 도구 접촉에 따라 젖은 상태 변화 | 해당 부위에만 변화하고 완료 표시와 외형이 맞는다 |
| 추가 빗질·가위 | 엉킴·털 방향·윤곽 정돈 | 기존 도구와 다른 손질 경험이 있고 동물에 맞는 작업이다 |
| 전체 절차 | 접수·요청·목욕·건조·손질·결과 연결 | 채택한 작업끼리 상태가 이어지고, 새 방문과 개별 기록이 구분된다 |
| 꾸미기 | 무료 액세서리·색·사진·가게 표현 | 2D·3D 적용과 저장이 일치한다. 실제 판매는 별도 결정이다 |

초기 물·거품 표현은 영역·텍스처·효과로 검증할 수 있다. 복잡한 물리 시뮬레이션을 기본 요구로 두지 않는다.
시간 제한·동물 기분 관리·도구 구매·추가 품종도 확장 후보이며 현재 첫 시제품의 필수 범위가 아니다.
